## 1. System Overview

本システムは、学校・スポーツ団体と個人指導者をマッチングするWebシステムである。学校側は指導者募集案件を掲載し、個人指導者側は案件検索・応募を行う。運営管理者は学校・指導者の登録審査、利用状況の把握、トラブル対応を行う。

参考サイト「BACK ATHLETE」は、アスリートを支える指導者・トレーナー・アナリスト等に焦点を当てた情報発信の色が強い。本システムでは、その思想を踏まえ、単なる求人掲示板ではなく、指導者の専門性・実績・想いを可視化し、学校/団体が適切な支援者を探せる仕組みを目指す。

トップページの最重要導線は、PPTX参考画面のような「地図から探す」セクションとする。ユーザーは日本地図上の都道府県または都道府県検索フォームから、近くの地域にいる指導者を直感的に探せる。地図には都道府県ごとの登録指導者数を表示し、地域移行を踏まえた部活動指導者探しを支援する。

### 2.1 運営管理者

運営管理者は、システム全体を管理する。

主な役割:

- 学校/団体アカウントの登録審査
- 個人指導者アカウントの登録審査
- 登録情報、案件、応募状況の確認
- 不適切な案件・プロフィールの停止
- 問い合わせ、通報、トラブル対応
- 利用状況の把握

### 2.2 学校/団体アカウント

学校、部活動、クラブ、スポーツ団体など、指導者を探す側のアカウント。

主な機能:

- 団体プロフィール登録・編集
- 指導者募集案件の掲載
- 応募者の選考・連絡
- 所属指導者または応募指導者の一覧確認
- 指導者プロフィールの閲覧

### 2.3 個人指導者アカウント

指導者、トレーナー、メンタルコーチ、栄養士、アナリスト、リハビリ担当など、学校/団体を支援する個人アカウント。

主な機能:

- プロフィール・実績登録
- 募集案件の検索・閲覧
- 案件への応募
- 学校/団体プロフィールの閲覧
- 応募履歴・調整状況の管理

## 3. MVP Scope

初期開発では、次の範囲をMVPとする。

- ログイン/ログアウト
- アカウント種別ごとの登録
- 管理者による登録審査
- トップページの全国地図検索
- 指導者プロフィール登録・一覧・詳細
- 団体プロフィール登録・一覧・詳細
- 案件登録・一覧・詳細
- 指導者による案件応募
- 学校/団体による応募者確認
- 応募ステータス管理
- 管理者ダッシュボード

MVPでは、決済、契約電子署名、チャット、レビュー機能は必須外とする。ただし、後続拡張を見据えてデータ構造には余地を残す。

- メールアドレスとパスワードでログインできる。
- ユーザー種別は、管理者、学校/団体、個人指導者の3種類とする。
- 学校/団体、個人指導者は登録後すぐに全機能を使えず、管理者承認後に公開・応募可能とする。
- パスワードリセット機能を用意する。

### 4.3 トップページ/地図から探す

トップページは「全国部活指導者マップ」のように、地域から指導者を探す体験を中心に構成する。

主な表示要素:

- サービスロゴ/名称
- グローバルナビゲーション
- ログイン
- 新規会員登録
- メインコピー
- 登録指導者数
- 都道府県選択
- 専門項目/指導分野選択
- 検索ボタン
- 日本地図
- 都道府県ごとの登録指導者数

地図検索の仕様:

- 日本地図は47都道府県をクリック可能にする。
- 各都道府県には登録済みかつ公開中の指導者数を表示する。
- 都道府県をクリックすると、選択した都道府県で絞り込んだ指導者一覧へ遷移する。
- 都道府県と専門項目を選んで検索すると、両条件で絞り込んだ指導者一覧へ遷移する。
- 登録指導者数が0件の都道府県も表示し、クリック時は0件結果画面を表示する。
- 地図上の色は件数帯または地域ブロックで変化させ、登録数の多い地域を視覚的に把握できるようにする。
- スマートフォンでは地図を縮小表示または地域ブロック別リストに切り替え、都道府県を確実に選択できるようにする。

会員申込導線:

- 指導者を探している関係者向けの「閲覧会員」申込導線を用意する。
- 部活動指導を希望する指導者向けの「指導者会員」申込導線を用意する。
- 指導者会員には、プロフィール登録だけでなく、資格・検定・研修等の確認導線を置けるようにする。
- 注意事項、利用条件、会費がある場合の説明ページを用意する。

## 5. Workflow

### 5.1 指導者登録から応募まで

1. 指導者がアカウント登録する。
2. 指導者がプロフィールと実績を入力する。
3. 管理者が登録内容を審査する。
4. 承認後、指導者プロフィールが検索対象になる。
5. 指導者が案件を検索する。
6. 指導者が案件に応募する。
7. 学校/団体が応募内容を確認する。
8. 学校/団体と指導者が調整する。
9. 採用/不採用/辞退等のステータスを更新する。

### 5.2 学校/団体登録から募集まで

1. 学校/団体がアカウント登録する。
2. 団体プロフィールを入力する。
3. 管理者が登録内容を審査する。
4. 承認後、案件登録が可能になる。
5. 学校/団体が募集案件を掲載する。
6. 応募者を確認する。
7. 指導者プロフィールを確認する。
8. 調整結果をステータスに反映する。

### 5.3 管理者審査

1. 管理者が申請一覧を確認する。
2. プロフィール、連絡先、公開内容を確認する。
3. 必要に応じて差し戻し理由を入力する。
4. 承認、否認、停止のいずれかを実行する。
5. 対象ユーザーに通知する。

## 9. Matching Logic

MVPでは検索・絞り込みを中心に実装する。自動推薦は後続拡張とする。

基本マッチ条件:

- 競技が一致する
- 指導分野または募集職種が一致する
- 都道府県または対応可能都道府県が一致する
- 対象年代が一致する
- 希望額が団体条件と大きく乖離しない
- 必要資格を満たす

後続拡張:

- 条件一致スコア
- 管理者推薦
- 人気/応募率を考慮した並び替え
- プロフィール充実度スコア
- 面談後評価

## 11. Non-Functional Requirements

### Security

- パスワードはハッシュ化して保存する。
- 個人連絡先は原則非公開にする。
- 管理者以外が他者の非公開情報を閲覧できないようにする。
- ファイルアップロードでは拡張子、MIMEタイプ、サイズを制限する。
- CSRF、XSS、SQL Injection対策を行う。

### Privacy

- 公開/非公開設定のある項目は、画面表示とAPIレスポンスの両方で制御する。
- メールアドレス、電話番号、責任者情報は公開画面に出さない。
- 退会/停止時のデータ保持ルールを決める。

### Usability

- スマートフォンでも登録・検索・応募ができるレスポンシブUIにする。
- 入力フォームは下書き保存または途中保存を検討する。
- 一覧画面では検索条件を保持する。
- 必須項目、任意項目、公開/非公開を明確に示す。

## 15. Acceptance Criteria For MVP

- 管理者、学校/団体、指導者が別々の権限でログインできる。
- TOPページに全国地図が表示され、都道府県ごとの公開指導者数が確認できる。
- 都道府県クリックまたは検索フォームから、条件を保持した指導者一覧へ遷移できる。
- スマートフォンでも都道府県を選択して指導者を探せる。
- 指導者がプロフィールを登録し、管理者承認後に一覧表示される。
- 学校/団体がプロフィールを登録し、管理者承認後に案件を作成できる。
- 指導者が案件を検索し、応募できる。
- 学校/団体が応募者を確認し、応募ステータスを更新できる。
- 管理者が登録審査、案件確認、応募状況確認を行える。
- 非公開項目が公開画面に表示されない。
- スマートフォンとPCの主要画面で操作できる。
